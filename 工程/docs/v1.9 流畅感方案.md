## 一、我听懂的是两件事

**第一件：你不知道东西存上了没有。**

橡果现在有 12 个能打字的地方，提交规则**互相矛盾**——同样是「打了一半点到别处」：

| 你在哪打字 | 现在会怎样 |
|---|---|
| 随手记、任务卡整句改、加子任务 | 悬着，不存也不丢 |
| 清单改名、设置里的快捷键 | 自动存 |
| 侧栏新建清单、日历格里快记 | **直接丢掉** |
| 任务标题、备注、子任务名、习惯名 | 每敲一个字就存一次 |

而且**存上了以后没有任何反馈**。整个软件里，只有「完成 / 删除 / 顺延」这类操作会给你一句提示，
打字类操作一句都没有。所以你的感觉是对的——**这不是你多疑，是它真的没告诉你**。

你说「不一定需要一个按钮」，我的理解是：你不要多一次点击，你要的是**存上了得让我看见**。

**第二件：快 ≠ 流畅。**

你自己那句话点得很准：「点开切换收缩，很流畅迅速，但恰恰缺乏那种流畅感」。
橡果现在几乎所有切换都是**0 毫秒瞬变**——瞬变不是流畅，是生硬。
现代 App 的流畅感来自「东西是长出来的、挪过去的」，不是「啪一下换了一张图」。

最刺眼的一处：**点开一件事**。行消失、卡出现、底下整列瞬间往下跳 250 像素。
而且它只有出现的动画、没有收起的动画——收起是硬切。

顺带查出来的实情：全项目一共写了 **9 种不同的动画时长**（.1/.12/.14/.15/.16/.18/.22/.25/.45 秒），
各写各的，没有统一。真正做得对的只有一处（手机上侧栏抽屉的缓动曲线）。

## 二、A 组：让你知道「存上了」

| | 现象 | 改成什么 | 你能感觉到的差别 |
|---|---|---|---|
| A1 | 三套失焦规则并存，有的地方点走就白打 | **统一成：点走 = 存下；只有 Esc 才丢弃**。侧栏新建清单和日历快记这两处，空的就丢、有字就存 | 再也不会「打了一半点走就没了」 |
| A2 | 存上了零反馈 | 提交瞬间输入框边框亮一下（200 毫秒），右边浮出一个「✓」停 800 毫秒淡出 | 一眼知道存上了。**不加按钮**，正是你说的那样 |
| A3 | 整句改打到一半按 Esc，卡片直接收走，句子没了 | Esc 分两级：第一下只把这句还原，第二下才收卡片 | 不会手一抖前功尽弃 |
| A4 | 清单名是个「看不出能改」的标题，回车还会插入换行 | 换成正经输入框，鼠标移上去露一圈淡边框，回车 / 点走都是存，Esc 还原 | 一看就知道能改 |
| A5 | 标题打 20 个字 = 往撤销栈里塞 20 份快照（上限 50 份），之前删掉的东西再也撤不回来 | 同一个字段 800 毫秒内的连续输入合并成一份快照。**照旧每个字都存盘，一个字都不会丢** | Ctrl+Z 撤的是「刚才那件事」，不是「刚才那个字」 |
| A6 | 日期弹层里两套规矩：点「今天/明天」立刻生效，选日期时间却要再点「✓ 确定」 | 统一成一套 | 不用猜这次要不要点确定 |
| A7 | 子任务名、备注、习惯名同样每敲一字就存、同样零提示 | 复用 A2 的回执，停手半秒闪一下 | 同上 |

> A5 是这组里唯一有风险的一条——它动的是全应用**唯一的写入口**。
> 所以它会单独配一批测试，而且「照旧逐键存盘」这条底线不动：**撤销变好用，但绝不会丢字**。

## 四、我的建议

**做第一档：A1–A7 全做 + B0/B1/B2/B4/B5/B7/B8。**

理由：第一档全是**消除硬跳和补上缺失的反馈**，做完你会觉得「顺了」，但橡果还是橡果，
不会变成一个动来动去的软件。第二档是往上加氛围，回报递减，而且是最容易做过头的部分。

**美学底线我会守住**（这条不用你操心，写在这里备查）：
位移不超过 8 像素、时长不超过 220 毫秒、不做弹簧回弹、不给任务行加浮起阴影、不做左右滑页。
橡果的调性是「纸感、温暖、克制」，动效堆砌一旦破坏它，返工比加动画本身还贵。

**手机端本轮不动**（按你定的规矩）。但样式是两端共用的，等你说手机端可以追的时候，
这些动效会一起过去，到时候要在低端安卓机上再走一遍——低端机上位移动画最容易掉帧。

## 六、落地时改了主意的三条（2026-09-01）

- **B7「换主题的颜色渐变」撤回，换主题回到瞬间齐切。**
  原因是**半做比不做难看**：只给 body / 侧栏 / 任务卡 / 随手记这四块面加了底色过渡，
  而前景色（几十处显式写死 `--ink-2` / `--ink-3`）仍是瞬切。浅↔深切换的中段，
  浅色标题压在还没爬到位的浅底上，打开着的任务卡标题对比度掉到约 1.2:1，几乎看不见；
  节奏也被撕成三档（180ms / 搭 hover 便车的 120ms / 0ms 瞬切）。
  想要完整版，**必须把这些面上的前景色一并纳入同长过渡**——几十处，性能与维护都不划算，
  所以这一版不做。整齐的瞬切好过撕裂的渐变。

- **B5 的「收起 / 展开子任务」总开关改走硬切。**
  `grid-template-rows` 上不了合成器，每帧都要重算轨道并回流其下方的全部内容，
  而这个按钮存在的理由恰恰是「行太多了」——它会在最需要快的时候最卡。
  一次性翻掉整列本来也不该有动画。**单条小三角照旧有高度动画**（一次只动几行，是安全的）。

- **「登录过就在卸载时连数据一起清」撤回**（本文附录里原来那条已改正）。三个理由：
  ① 卸载程序判断不了「有没有改动还没传上云」，删了就是一个没有闸门的破坏性动作；
  ② 数据文件夹是你拿系统对话框随便挑的一个已有目录，橡果并不独占它——递归删下去会连累里面别的东西；
  ③ 卸载向导那个「删除应用程序数据」勾选框的判断排在钩子**之后**，钩子先删了，
  就会出现「界面显示的和实际做的相反」。
  现在的口径以 `工程/README.md` 的「登出 / 卸载会留下什么」一节为准：
  **卸载只删登录令牌和浏览器缓存，任务数据一个字不动。**

- **「放弃」的事从清单类视图里也退出去了**（2026-09-01 收口时定的口径，**要你确认一下**）。
  原先是「留在清单里，划掉加个灰标签」，现在改成**跟「已完成」完全一样的待遇**：
  从 随手记 / 清单 / 需求方 / 标签 四个视图里整条隐藏，侧栏角标和统计里的未完成数也不再算它。
  改的原因是原先那套导致同一个「还欠几件」在侧栏和统计页算法不一样、给出两个数。
  放弃的事只在「已完成 → 放弃的」里能找到，取消放弃也从那儿点。
  **你要是更想要「清单里留着划掉那条当上下文」，说一声，我把这四个视图连同角标和统计一起改回去**
  （只改一半就会再次出现两个数打架）。

## 附：另一件我按你原话做了、但要跟你说清楚的事（不用回复，除非你要改）

你说的「登陆账号之后，账号登出或者删除软件，本地不留日志，只留云端」，我会这样落地：

- **退出登录时清空本机数据**，但前面加两道硬闸门：
  ① **当场同步一次并且必须成功**才允许清（不看「看起来是干净的」那个内部标记——它重启就归零，
  会把离线改过的东西谎报成已同步）；② 同步不成功就**不清**，并给你一个「先导出一份再清」的出口。
- **从来没登过账号的人，一个字节都不会删**——本地是他唯一那一份。
- **「注销账号」那条路径反过来：绝不清本地**。否则你点一下，云端和本机一起没了，找不回来。
  那一步的提示会写清楚「云端已经删干净，本机这份是你唯一剩下的」。
- **卸载**（⚠️ 这条 2026-09-01 落地时被推翻了，下面是最终口径，见第「六」节第三条）：
  卸载只删登录令牌和浏览器缓存，**登没登过账号都一样，你的任务数据一个字都不动**。
  删不删任务数据只跟卸载向导里那个「删除应用程序数据」勾选框走（默认不勾）；
  你自己换到别的盘的那个数据文件夹更是碰都不碰。
  **「删掉软件、本机不留」的正路是：先在软件里点「退出登录并清空本机」（那条有真闸门，
  当场同步成功才肯删），再卸载。**
- ⚠️ **每日备份那 30 份只在本地、云端没有**，清空 = 30 天历史永久消失。确认框里会点名说到这一层。
- ⚠️ 这条**推翻了 v1.5.0 白纸黑字写给你的承诺**（「退出登录，本机数据一条不动」）。
  更新日志和设置页的说明会一起改口径，不留两句打架的话。
