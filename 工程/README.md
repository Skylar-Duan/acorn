- **回收站**：标题、保留期限和操作分列，恢复是主要动作，子任务显示母任务上下文；手机上操作移到第二行。
- **手机跟随**：共有字体、底面、按钮、抽屉和内容页样式已修改，保留底部导航、滑动与原有入口。手机标题直接解析、独立子归类编辑、创建分类确认弹窗仍按手机设计另行跟随；桌面这些新能力不能据此视为已在手机提供。

## Windows Plus

只下载一个完整Windows包，登录后按服务器确认的Plus资格显示图片附加功能；其他办公功能、界面与更新通道完全共用。已授权Bower账号在设置独有Plus启停开关，只影响本机功能显示，不撤销账号资格、不删图；其他Plus账号没有开关并自动开启。未授权、退出登录或关闭Plus时不展示图片入口、缩略图或计数，读取、修改、合并、备份及导出仍保留可选 `images` 与未知字段，数据版本8；恢复Plus原图照常显示。

输入只接受 JPEG/PNG/WebP；解码前限制原文件20MiB、四千万像素及单边16384，压缩后为最长1920像素/单张最多256KiB的JPEG，每个任务或子任务最多8张。所有新增图以内联 data URL 合计20MiB控制；复制到循环历史的既有图保留。离线可以添加，容量不足只拦新增图片。Plus账号云账本上限32MiB，普通账号5MiB；云超限时保留本机数据并提示，完成和删除本机任务始终可用。

主任务、子任务、记一条和Alt+Space支持在文字输入处粘贴或拖入图片；子任务小加号也能多选本地图片。保存后右侧只显示一枚缩略图，多张时叠层计数，点击展开完整图片集合。图片处理或选择期间若关闭Plus、登出、换号或切换目标，旧异步结果不会写入任务。

`node scripts/build-app.mjs desktop`生成统一`Acorn_<版本>_x64-setup.exe`；加`--beta`走独立测试通道。旧`--ultra/--plus`参数明确拒绝，避免误出第二个包。公共发布器原样复制同一安装包到旧Ultra私有更新路径，旧客户端能正常迁入统一包，无需重新编译另一版本。历史验证码授权继续被服务器识别，当前网站不再提供第二种安装包或验证码下载页面；管理员仍可查询历史授权。App不弹Plus授权账号登录提醒。

大账本收发正文最多等待120秒；账号查询20秒。已确认同步且本机未变时，自动检查先读云端修订号；相同则不重传整本，修订号变化/本机变动仍完整合并同步。登出、切换账号或账本后，旧在途响应不写回新上下文。

- **记录**：一句「周五下午3点 提交周报 #工作 @李哥 !高」，日期、时间、清单、需求方、优先级自动识别。
- **安排**：今天 / 计划（列表与四象限两种视图）/ 日历拖拽改期。
- **执行**：番茄钟专注计时暂时收起（代码与历史记录保留，待方案确定后再开放）。
- **回顾**：完成热力图、需求方工作量分布、每周回顾导出 Markdown。

## 功能一览

- **记一条（统一记录入口）**：电脑上是侧栏顶上那颗「＋ 记一条」（`Ctrl+1`），点开是屏幕中间一张输入卡；手机上是右下角那个 ＋。两种记法并排给——**打字**用中文自然语言（明天 / 周五 / 下周三 / 8月20日 / 十月底之前 / 每周一三五 / 下午3点…，配 `/清单`（新名字先确认）`#标签` `@需求方` `!高`，全角半角与 `！！！` 都认，输入时自动补全已有项）；**不想背语法**就用下面一排按钮点着选日期 / 清单 / 需求方 / 重要性 / 重复，选中会一直生效。**记完不关窗**，连着记几条不用重开，`Esc` 关
- **习惯**：重复着做的事单独一个分类，一个圈点一下就是打卡；连续多少次、本周七格、整月日历、最长连续、近 30 天完成率；忘了可以补打任意一天。习惯**不会逾期**，也不混进今天/计划。习惯页还有一组「重复的计划」：所有带循环的计划和循环子任务（「母 › 子」）按下一次的日子列在这里，点开就是计划页那一行；每个习惯右边写「下次 周三」
- **侧栏分组与排序**：电脑顶上一颗「＋ 记一条」，导航入口可整组拖动、右键改显示名或隐藏；清单、需求方、标签独立收展，展开内容缩进，数量最右对齐。拖动时实体横条移动、周围模块实时让位，松手保存、Esc取消；功能区设置用两排小按钮隐藏/恢复入口。清单组内顺序跟数据走，需求方及模块排布保存在本机。手机保留底部导航与更多页
- **视图**：**计划** · 日历 · 今日任务（逾期置顶；手机上仍叫「今天」、仍是开机页）· 习惯 · **已完成** · 统计 · 回收站（显示每条保留期限，可单条恢复/彻底删除，电脑任务拖入即删）。专注暂时收起，侧栏里看不到
- **计划**：所有还没做完的事都在这儿，两种看法一键切换——
  **列表**按时间分段（逾期 / 今天 / 本周 / 本月 / 半年内 / 更远 / 未安排；本周到周日、本月到月底、半年内到往后第六个月的月底，跟「~半年内」同一个边界），或者换成按重要性分段（高 / 中 / 低 / 普通，每档内部按时间排）；
  **四象限**用任务/子任务散点表示重要度与截止日期，近期刻度更宽；点开查看真实任务卡，拖动时浮卡预览日期和重要度，松手一次保存并可撤销
- **已完成**：收场了的事都在这儿，按 过去一周 / 过去一个月 / 更早 分段，按实际完成时刻倒序，最近完成的在上；同刻稳定，旧记录没有完成时刻的放最后。日历当天议程、今日完成列表和卡内已完成子任务同样倒序。点圆圈就能放回去。顶上「做完的 / 放弃的 / 全部」三选一，默认「做完的」，选了会记住
- **放弃**：有些事就是不做了，但它没做成。圆圈只管完成，放弃是标题旁边一个灰色小标签「已放弃」（任务和子任务都能标，入口在任务卡右下角和右键菜单）。标了之后它**跟做完的事一个待遇**：从所有待办视图里退出去（今天 / 计划 / 四象限 / 日历 / 清单 / 需求方 / 标签），侧栏和统计页那些「还欠几件」的数字也都不再算它，收进「已完成」的「放弃的」里；取消放弃就回到未完成，进撤销栈。**统计里单独算一档，一件都不并进完成数**。循环任务放弃只是这一轮不做，下一轮照常来（要彻底不做请删除）
- **需求方维度**：每件事记录「为谁做」，**一件事可以挂好几个人**（`@李哥 @王姐`），侧栏按人聚合、每人名下都看得到，统计页看各需求方工作量
- **任务**：备注、循环、到点系统通知提醒、顺延计数
- **子任务按「下一步」排**：一件事还剩几个子任务没做，列表里就占几行（「写周报 › 画趋势图」），母任务行先收起，全做完才回来收尾；子任务的日期与重要性**默认等于母任务**（小签上淡显继承来的值），也可以单独排期（拖到侧栏、展开后右键「调整日期」、任务卡里点日期，只动这一条）；收成一行时右键出的是「整件事」的菜单，改的是母任务。今天 / 计划 两个视图口径一致
- **子任务链可折叠**：列表行首三角可只留下一步，行尾+N提示后续，计划页总开关可一次收起全部。电脑任务卡待办收起保留前三条，三条以内全显、超过三条可展开其余，数量与新增入口保留并记住本机偏好；完成前面的步骤后自动补入后续。备注高度随内容变化；已完成的子任务按完成时间倒序，攒到3条可另外折叠。133条合成步骤已覆盖边界和压力场景
- **子任务快捷语法**：新增时支持日期、时间、重要性与循环。电脑界面还支持在新增或直接改标题时写`@需求方 /清单`，去重追加到这一步、末尾小签可×移除，母任务归类不变；`#标签`保留为普通正文。手机独立子归类与直接改标题解析仍待设计跟随
- **顺手**：任务行右键有完整菜单；任务可拖到侧栏（今天=改今天，计划=弹日期选择，清单/需求方=归属）
- **选日子只有一套规矩**（2026-09-22 起全应用同一份，`core/options.ts`）：今天 / 明天 / 本周末 / 下周末 / 本月末 / 选日期…，本周末按设置里的周末日算，跟前面某项撞同一天的不显示。任务卡、记一条、电脑右键「调整日期」（手机长按叫「安排日期」）、侧栏「安排到哪天？」、顺延都是这一套。点预设 = 设好并关掉；任务卡里点日历的某天 = 立刻生效但弹层留着，好接着设时间；时间点完鼠标一移开就生效，翻月只是翻着看不会改日期。没有常驻日期框的地方（顺延、右键）「选日期…」点开是日期框 +「确定」。**顺延**：电脑上逾期组「全部顺延 ▾」、多选浮条「顺延 ▾」、过期行尾「顺延 ▾」，手机上左滑 / 长按「顺延」、今天页「全部顺延 →」；早于或等于这件事现有日期的项不出现，不会把日期往前拉，只有日期往后挪才算一次顺延；`Ctrl+→` 仍是原日期加一天
- **循环也只有一套**：每天 / 每个工作日 / 每周X / 每月X号 / 每隔几天… / 自定义…（天 / 周 / 月面板），有循环时末尾「不重复」；「每周X / 每月X号」按这件事的日期算，没日期按今天。任务、记一条、习惯（习惯没有「不重复」）都是这一套
- **直接改标题（电脑界面）**：主/子标题识别显式快捷标记，写`~明天`替换日期，没提到的日期、钟点、重要性仍保留；回车或点走提交、Esc取消。母任务`@`和`/`替换归类，子任务则追加自己的归类。未知名字先统一确认名称、颜色与图标，中途取消整笔编辑不留下半份分类
- **写法说明**：「记一条」标题旁边的 `?`（设置里也有一个入口）打开一个独立窗口，一组举例卡片：左边是要打的那句，右边是当场解析出的结果
- **托盘常驻**：关窗进托盘；`Alt+Space` 全局唤起「记一条」小窗（可改键）
- **键盘流**：`Ctrl+K` 命令面板 · `Ctrl+F` 搜索 · `Ctrl+Z` 撤销 · `Ctrl+D` 完成 · `Ctrl+→` 推明天 · `Ctrl+1` 记一条 · `Ctrl+2~5` 切视图（计划 / 日历 / 今日任务 / 习惯，跟侧栏同序）
- **六款自然主题**：森林 / 海洋 / 星空 / 沙漠 / 雪山 / 南极，深浅双模式；干净中性底面与淡风景，主题色用于选择、按钮、日历块和小标记，不叠纸纹
- **云账号与跨设备同步**（可选，不登录一切照旧）：邮箱注册 + 验证码激活，登录后多台设备同一份任务。本机那份和云端那份是**合起来**的不是覆盖，同一件事两边都改过以改得晚的为准；断网、服务器挂了都不影响本地使用。改完静置几秒自动传，**每天至少补一轮**（应用回到眼前时才查，不在后台守着）。登录后可以「从云端覆盖到这台设备」拿回整份数据；退出登录有两条常驻出路——**「退出登录并清空本机」**（清之前必须当场同步成功，否则一条不清）和**「只退出登录，保留本机」**（本机一条不动），见下面「登出 / 卸载会留下什么」
- **数据安全**：数据是一个人类可读的 JSON；原子写入 + 崩溃恢复；每日自动备份保留 30 份；回收站 30 天；导入导出 JSON/CSV/Markdown；版本升级自动无损迁移旧数据

## 数据存哪

默认在本机 `%APPDATA%\com.cdpandas.acorn\userdata\`，装完开箱即用。
安卓上是应用私有目录 `/data/data/com.cdpandas.acorn/files/userdata`（手机上没有「换文件夹」，跨端靠云账号）。
设置页可把数据文件夹换到移动硬盘 / 网盘（换电脑打开是同一份任务；指针存 `%APPDATA%\com.cdpandas.acorn\config.json`，并记录用过的位置，数据本体不动）。

**不会让你以为数据丢了**：启动时如果数据文件夹是空的，橡果会先扫一遍数据可能待着的地方（默认目录、用过的目录、exe 旁边、被沙箱化的镜像目录），找到有内容的就列出来让你选——**你不点，它什么都不写**。选定的文件夹当下不可用时（硬盘没接等）会友好提示并可重试，不会闪退、不会悄悄新建空数据覆盖。

**导入导出**：导出的 JSON 带信封（`app` / `schema` / `appVersion` / `exportedAt` + 完整数据），老版本导出的裸数据也照样能导入；「导出→导入→再导出」逐字节一致，以后接服务器同步用的是同一份口径（`src/core/transfer.ts`）。

## 登出 / 卸载会留下什么

前提分两种，行为完全不同：

**从没登录过云账号** —— 数据只有本机这一份，橡果绝不替你删。设置里根本没有「清空本机」这条路，
Rust 侧的清除命令自己也会拒绝（判断依据是 `auth.json` 在不在）。卸载时，用户数据只跟安装程序里
那个「删除应用程序数据」勾选框走（默认不勾）——**登没登过账号都一样，卸载钩子不碰用户数据**。

**登录过云账号** —— 数据的家在云端，本机这份是副本：

- **两条出路常驻**：「退出登录并清空本机」（默认动作，排前面）与「只退出登录，保留本机」。
  后者不是只在出错时才冒出来的补救——换账号、暂停同步都走它，本机一条不动。
- **退出登录并清空本机**：清之前会**当场同步一轮，成功了才删**；断网 / 登录过期 / 版本太老一律不删，
  并给出「先导出一份 JSON」这条出口。
  判断依据只认「这一轮同步真的成功了」，不看进程内的 `dirty`（重启就归零，会把离线改的东西谎报成干净）。
  闸门那一轮走 `syncNow({force:true})`：**不许复用在途的那一轮**（它的快照是几秒前的数据），
  而且同步成功只有在「上传的就是当前这份」时才敢把 `dirty` 抹掉——否则往返期间顺手记的那条
  会被这次成功谎报成已上传，紧接着连盘一起删掉。
- **删的是这些**：`data.json` 与它的中间态（`.tmp` / `.old` / `.corrupt-*`）、整个 `backups/`
  （每日 30 份 + `pre-restore-*` + `pre-import-*`）、`smoke-report.json`、`.acorn-probe`、`auth.json`，
  并把 `config.json` 的 `recentDirs` 清空（不清的话下次启动的「找回数据」会把刚删掉的推荐回来），
  以及 `acorn-` 开头的那几个 localStorage 偏好。
  **范围跟 `candidate_dirs()` 一样宽**：当前目录、默认位置、`%APPDATA%` / `%LOCALAPPDATA%` 下的
  `userdata`、exe 旁边、沙箱镜像、recentDirs 全都清一遍（换过数据文件夹的人，旧目录里躺着的是
  `set_data_dir` 复制过去时留下的完整旧账本，只清当前目录等于白清）。
  **只按文件名删，绝不 `remove_dir_all` 目录本身**——数据文件夹是用户拿选择器随便挑的一个已有目录。
  清完在 `config.json` 里留一个一次性的 `freshStart`，下次启动用空账本开局、跳过落盘
  （否则 `defaultData()` 那两条每次换新 id 的「工作」「生活」会被推上云，各设备各多一对）。
  ⚠️ **每日备份只在本机、云端没有**，清空 = 30 天历史永久消失，确认框里会点名说这件事。
- **从云端覆盖本机时，`pre-restore` 备份是硬前置**：`inTauri` 下备份写不成就抛错中止，
  一个字节都不写（确认框刚承诺过会先备份，吞掉失败照样覆盖等于说话不算话）。
- **注销账号相反：本机一个字不动**。先删云端再断开登录态，之后本机这份是唯一剩下的。
- **401 被踢下线（非自愿登出）不清任何东西**。清空是 `wipe.ts` 的显式动作，
  绝不是「session 变 null」的副作用——一次令牌过期就抹掉全部本地数据，而那一刻恰恰同步不上去。
- **卸载（Windows）**：`src-tauri/nsis-hooks.nsh` 挂在 `bundle.windows.nsis.installerHooks` 上。
  `NSIS_HOOK_PREUNINSTALL` **只做无害清理**：删 `auth.json`（登录令牌）与
  `%LOCALAPPDATA%\...\EBWebView`（WebView2 缓存）。这两样都不是用户内容。
  ⚠️ **钩子里绝不许有破坏性动作**，三个理由都成立过：
  ① 本项目的 App 内升级走 `openPath` 拉安装器、不带 `/UPDATE`，`$UpdateMode` 在安装器和
  uninstaller 两侧都是 0，`$UpdateMode <> 1` 这道闸（保留着）在升级路径上很可能不成立——
  钩子里有破坏性动作就等于每升一版删一次数据；
  ② 用户自选的数据文件夹是文件夹选择器随便挑的一个已有目录（`set_data_dir` 不追加子目录），
  橡果并不独占它，`RMDir /r` 会连无关文件一起删，数据放共用盘时还会波及另一台机器；
  ③ 模板里那个「删除应用程序数据」勾选框的判断排在本钩子**之后**，钩子删了数据就等于
  界面显示的和实际做的相反。
  用户数据的删除完全交回那个勾选框（模板自带，只动 `$APPDATA\<id>` 与 `$LOCALAPPDATA\<id>`）。
  **「删软件本地不留」的正路是应用内的「退出登录并清空本机」**（那条有真闸门）：
  要彻底清干净，先在软件里清，再卸载。
  （`datadir.txt` 仍由 Rust 侧写着，钩子不再用它删任何东西。）
  **别去改 `src-tauri/target/release/nsis/x64/installer.nsi`**，那是每次 build 重新生成的产物。
- **卸载（安卓）**：应用私有目录随卸载消失；`AndroidManifest.xml` 已加 `android:allowBackup="false"`，
  免得 data.json 和令牌进 Google 自动备份、换机时被复制过去。代价是换手机不能靠系统迁移带走数据，
  只能用云账号登回来。
  ⚠️ `src-tauri/gen/` 整个在 `.gitignore` 里，重新 `tauri android init` 会把这个属性冲掉——
  出安卓包之前先确认 `<application>` 上还有 `android:allowBackup="false"`。
- **清不掉的**：应用内的清空动作删不掉 WebView2 自己的缓存目录（进程还占着），那要靠卸载钩子；
  你自己导出到别处的文件橡果也不会去动。文案上不能承诺「登出即片甲不留」。

**换机器 / 清空之后怎么拿回来**：设置 → 云账号 → 「从云端覆盖到这台设备」。
从云端拉最新一份**整份覆盖**本机（单向，不是合并：本机有、云端没有的会消失），
覆盖前自动在 `backups/` 里留一份 `pre-restore-*.json`，云端为空或拉取失败时一个字都不动本机。

## 开发

```bash
npm install
npm run dev          # tauri dev（需要 Rust + VS C++ 工具链；Rust 若不在 PATH：$env:Path += ";$env:USERPROFILE\.cargo\bin"）
npm test             # vitest 单元测试（解析/循环/统计/搜索/store）
npm run build        # 打 NSIS 安装包 → src-tauri/target/release/bundle/nsis/
bash scripts/build-android.sh   # 打安卓 APK → src-tauri/target/release/bundle/android/
```

**打安卓包有两道坎，脚本里都绕过去了**（换机器要先装 JDK 17 + Android SDK 34 + NDK 27 +
`rustup target add aarch64-linux-android` 等四个目标）：

1. **S 盘是 exFAT，不支持符号链接**。Tauri 要用符号链接把编译好的 `.so` 放进 `jniLibs/`，
   在 exFAT 上直接 `IO error: 函数不正确`。脚本先把工程镜像到 C 盘（NTFS）再打。
2. **Windows 默认不允许普通用户建符号链接**（要开「开发者模式」）。到 NTFS 上照样卡。
   脚本改成：让 Tauri 编完 Rust，然后手动把 `.so` 拷进 `jniLibs/`，再直接
   `gradlew assembleArm64Release -x rustBuildArm64Release`。

出来的 release APK 是未签名的，脚本用安卓官方 debug 密钥签好（口令固定 `android`，公开约定值）。
**上架商店要换成你自己的正式密钥**——那把钥匙丢了就再也无法更新已上架的应用，得你本人生成保管。

冒烟自检：`$env:ACORN_SMOKE="1"` 启动应用 → 自动跑「建任务→完成→落盘→重读校验」并写 `userdata/smoke-report.json` 后退出。

- 需求方顺序存在 `Settings.whoOrder`，设置不参与云同步，所以手机上排的顺序不会传到电脑，反之亦然。

- 桌面上靠 hover 才出现的操作（子任务行的放弃 / 删除），手机上必须常显（`@media (hover: none)`）——
  v1.10.0 走查抓到的，README 之外 `tests/` 里有守卫。
- 窄屏排版最常见的病是 grid / flex 子项缺 `min-width: 0` 被撑到 min-content 顶出屏幕（任务卡、设置折叠都栽过），
  新加容器先写上。安卓 15+ 强制 edge-to-edge，`index.html` 的 viewport 带 `viewport-fit=cover`，
  否则 `env(safe-area-inset-*)` 恒等于 0。

### 版本错位时的硬规矩（v1.9.1 重写）

因为桌面会跑在手机前面，一定会出现「云端数据比手机上那份新」的时候。此时：

- **一定不能拒绝读取用户之前的日志**（2026-09-01 用户定的产品原则）。比本机新的数据
  **照常读进来、照常改、照常存回去、照常同步**，弹一次「已有更新版橡果」的框
  （`components/NewerDataDialog.tsx`：现在更新 / 取消，取消照常用，每次冷启动再弹一次）。
  v1.9.0 那一整屏「版本过旧」的墙**已经拆了**
- **也不许把新数据按老格式理解一遍再存回去**——这一条照旧成立，而且是上一条的前提。
  靠三件事保证：`migrate` / `mergeData` 的返回值先铺开原始对象再覆盖已知键（顶层未知集合不丢）、
  `pruneGraveyard` 存整个墓碑对象不重建（墓碑上的未知字段不丢）、
  `version` 一律取 `max`（「这份本来是第几版」这个事实不丢）
- 客户端 `transfer.unpack` 只如实报 `schema` + `tooNew`，**那是事实不是判决**；
  `transfer.pack` 推送时报 `max(本机 DATA_VERSION, 读到的 schema)`
- 服务端那道闸**保留不动**：`vaults.schema` 只升不降，推送时 schema 比库里低直接 409。
  它守的是**已经发出去的 v1.9.0 及更老客户端**（那些版本确实会吃掉数据），
  v1.9.1+ 报 max 之后天然不触发。收到 409 时同步只是**暂停**（退避 6 小时 / 重开橡果重试），
  不再是重启都解不开的终态
- 手机上会顺带提示「这一版带了新的数据格式」并给下载按钮

### 出一次手机版要做的三件事

```bash
bash scripts/build-android.sh                                   # 1. 打包
bash server/deploy/publish-apk.sh <apk> [更新说明文件]           # 2. 发到更新服务器
#    -> 手机上「设置 → 版本更新」就能查到、直接下、直接装
#    3. 顺手把 APK 也传一份到 GitHub Release（备用下载）
```

`publish-apk.sh` 会自动从 `src/core/model.ts` 抠 `DATA_VERSION` 写进清单，客户端据此判断
这次更新是不是「不升就同步不了」。

### 出一次桌面版要做的三件事

```bash
npm run build                                                   # 1. 打 NSIS 安装包
bash server/deploy/publish-exe.sh \
  src-tauri/target/release/bundle/nsis/Acorn_1.9.0_x64-setup.exe [更新说明文件]   # 2. 发到更新服务器
#    -> 电脑上每次打开会自动查一次，也可以「设置 → 版本更新」手动查
#    3. 顺手把 exe 也传一份到 GitHub Release（备用下载）
```

跟安卓那条完全对称，只有三处不同：清单落在 `<public_dir>/windows/latest.json`、
接口是 `GET /api/desktop/latest`、版本号从 `Acorn_x.y.z_x64-setup.exe` 里取。

⚠️ **发版前 `package.json` 和 `src-tauri/tauri.conf.json` 两个版本号必须同时改**。
只改一个的话，包名里的版本跟应用内显示的版本对不上，装完还会一直提示有新版，无限循环。

⚠️ **改了 `server/app/main.py` 必须跑 `bash server/deploy/deploy.sh --code`**，
scp 单个文件不生效（tar 只打 app / tests / requirements.txt）。新增的 `windows/` 目录
由 `deploy.sh` 的 mkdir 建，第一次发桌面包前先跑一次完整 deploy。

关键设计：

- **数据只有主窗能写**。快速添加小窗解析后把结果发事件给主窗落库；说明窗只显示、不写任何东西——几个 webview 各有各的内存，绝不两处写同一个文件。
- **原子写**：临时文件写入 → 读回校验 → 旧文件挪开 → 转正。任何一步崩溃，启动时都能从中间文件找回完整数据。
